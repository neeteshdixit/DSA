# Chapter 1: Complete Introduction to Stack
===============================================================================

## Introduction

A stack is a linear data structure that follows Last In First Out, commonly
written as LIFO.

Hinglish idea:
Stack ko plate ki pile samjho. Sabse last wali plate sabse pehle uthti hai.

Stacks are one of the most important interview topics because they naturally fit
problems that involve:
- order of processing
- backtracking
- nested structures
- matching pairs
- previous or next greater/smaller logic
- expression handling

In Java, stack questions are often solved using:
- `Stack`
- `Deque`
- `ArrayDeque`
- custom array stack
- custom linked list stack

## LIFO

LIFO means Last In First Out.

If you push 1, then 2, then 3:
- 3 comes out first
- then 2
- then 1

Visualization:

```text
Push 1
Push 2
Push 3

Top
3
2
1

Pop -> 3
```

## Why Stack Exists

Stacks exist because many problems naturally need reverse order processing.

Stack helps when:
- the latest item must be processed first
- previous state must be remembered
- nested opening and closing symbols must be matched
- expressions must be evaluated in the correct precedence order

Real-world examples:
- browser back button
- undo in editor
- recursion call stack
- function call tracking
- parsing expressions
- DFS backtracking

## Memory Representation

A stack as a data structure is usually represented as:
- an array
- a linked list
- or an existing library structure like `ArrayDeque`

Conceptually, the top of the stack is the only end where insertion and removal
happen.

If implemented using array:
- elements are stored in contiguous memory
- top is an index
- push and pop move the top index

If implemented using linked list:
- each node points to the next node
- top is the head reference
- push and pop adjust the head

For Java recursion:
- function calls are stored in the JVM call stack
- each call creates a frame holding local variables and return address

## Internal Working

Stack operations only touch one end:
- push adds to top
- pop removes from top
- peek reads top

That makes stack operations simple and fast.

Key idea:
We never need to shift all elements like an array insert or delete in the middle.

## Pattern Recognition

Use stack thinking when the problem mentions:
- next / previous element
- balancing symbols
- nested expressions
- backtracking
- undo / redo
- reverse order processing
- nearest greater / smaller
- monotonic order
- top / current state

## Trigger Words

- `push`
- `pop`
- `peek`
- `top`
- `undo`
- `redo`
- `balanced`
- `parentheses`
- `expression`
- `next greater`
- `next smaller`
- `previous greater`
- `previous smaller`
- `histogram`
- `daily temperature`
- `stock span`
- `duplicate removal`
- `current minimum`

## Advantages

- simple LIFO behavior
- fast push and pop at one end
- useful for recursion and nested parsing
- good for matching and order-dependent problems

## Disadvantages

- no random access like arrays
- only top element is directly available
- not ideal for searching arbitrary values
- recursion-based stack can overflow if too deep

## Array vs Stack

Array:
- direct access by index
- fixed or resizable contiguous storage
- good for random access

Stack:
- restricted access
- only top is accessible
- good for reverse processing and nesting

Short rule:
- if you need any index, use array
- if you need top-only behavior, use stack

## Complexity

Typical stack operation complexities:
- push: O(1)
- pop: O(1)
- peek: O(1)
- isEmpty: O(1)
- size: O(1)

If using a dynamically resizing array, push is amortized O(1).

- Why are stack operations O(1)?
- What is the difference between stack and queue?

# Chapter 2: Stack Implementations and Java Stack APIs

## Introduction

Stack can be implemented in multiple ways.

In interviews, you should know:
- stack using array
- stack using linked list
- Java `Stack` class
- `Deque` as a stack
- `ArrayDeque` as the preferred modern stack

## 2.1 Stack Using Array

### Pattern Recognition

Use an array stack when:
- capacity is known or bounded
- memory should be contiguous
- implementation simplicity matters

### Trigger Words

- `implement stack`
- `array based`
- `top index`
- `capacity`

### Observation

The top element is tracked using an index.

### Brute Force

Shift the entire array on every push or pop.

### Optimal Solution

Keep a `top` variable and update only that index.

### Visualization

```text
arr: [10, 20, 30, _, _]
top = 2
```

### Dry Run

- push 10 -> top = 0
- push 20 -> top = 1
- push 30 -> top = 2
- pop -> return 30, top = 1

### Java Code

```java
class ArrayStack {
    private int[] arr;
    private int top;

    public ArrayStack(int capacity) {
        arr = new int[capacity];
        top = -1;
    }

    public boolean isEmpty() {
        return top == -1;
    }

    public int size() {
        return top + 1;
    }

    public void push(int x) {
        if (top == arr.length - 1) {
            throw new RuntimeException("Stack overflow");
        }
        arr[++top] = x;
    }

    public int pop() {
        if (isEmpty()) {
            throw new RuntimeException("Stack underflow");
        }
        return arr[top--];
    }

    public int peek() {
        if (isEmpty()) {
            throw new RuntimeException("Stack is empty");
        }
        return arr[top];
    }
}
```

### Template

```java
int top = -1;
int[] arr = new int[capacity];

push: arr[++top] = x;
pop:  return arr[top--];
peek: return arr[top];
```

### Complexity

- push: O(1)
- pop: O(1)
- peek: O(1)
- space: O(n)

### Edge Cases

- overflow when stack is full
- underflow when stack is empty
- capacity zero

### Mistakes

- using `top = 0` with wrong push logic
- forgetting to check overflow
- returning wrong top after decrement

### Interview Questions

- implement stack using array
- what happens when array stack becomes full?

### Company Questions

- implement stack from scratch
- design bounded stack

## 2.2 Stack Using Linked List

### Pattern Recognition

Use linked list stack when:
- capacity should be dynamic
- push/pop should always be O(1)
- you want to avoid fixed-size array limits

### Trigger Words

- `linked list stack`
- `node`
- `head`
- `dynamic size`

### Observation

The top of the stack is the head of the linked list.

### Brute Force

Traverse to the end of the list on every push or pop.

### Optimal Solution

Insert and remove only at the head.

### Visualization

```text
top -> [30] -> [20] -> [10] -> null
```

### Dry Run

- push 10 -> head = 10
- push 20 -> new head = 20 -> 10
- pop -> remove 20, head becomes 10

### Java Code

```java
class LinkedStack {
    private static class Node {
        int data;
        Node next;

        Node(int data) {
            this.data = data;
        }
    }

    private Node head;
    private int size;

    public boolean isEmpty() {
        return head == null;
    }

    public int size() {
        return size;
    }

    public void push(int x) {
        Node node = new Node(x);
        node.next = head;
        head = node;
        size++;
    }

    public int pop() {
        if (isEmpty()) {
            throw new RuntimeException("Stack underflow");
        }
        int val = head.data;
        head = head.next;
        size--;
        return val;
    }

    public int peek() {
        if (isEmpty()) {
            throw new RuntimeException("Stack is empty");
        }
        return head.data;
    }
}
```

### Template

```java
Node node = new Node(x);
node.next = head;
head = node;
```

### Complexity

- push: O(1)
- pop: O(1)
- peek: O(1)
- space: O(n)

### Edge Cases

- empty stack
- one node stack

### Mistakes

- forgetting to update size
- losing the old head

### Interview Questions

- implement stack using linked list
- why linked list stack is dynamic?

### Company Questions

- custom stack implementation
- stack class from scratch

### Size

# Chapter 3: Balanced Parentheses and Valid Parentheses
===============================================================================

## Introduction

Bracket matching is one of the clearest stack use cases.

When the input contains nested opening and closing symbols, a stack remembers
the most recent unmatched opening symbol.

## Pattern Recognition

Use stack when the problem asks about:
- parentheses
- brackets
- braces
- balanced string
- valid sequence
- matching pair

## Trigger Words

- `balanced`
- `valid`
- `parentheses`
- `brackets`
- `braces`
- `matching`
- `nested`

## Observation

An opening symbol must be matched by the most recent unmatched opening symbol.

That is exactly LIFO behavior.

## Brute Force

Repeatedly scan the string and remove matching pairs.

This is slow and messy.

## Optimal Solution

Push opening symbols.
On a closing symbol:
- check whether the stack top matches
- pop the top if it matches
- otherwise fail immediately

## Visualization

```text
Input:  ({[]})
Stack:  (
        ( {
        ( { [
        ( {
        (
        empty -> valid
```

## Dry Run

String: `({[]})`

- `(` push
- `{` push
- `[` push
- `]` matches `[` pop
- `}` matches `{` pop
- `)` matches `(` pop
- stack empty -> valid

## Balanced Parentheses

Balanced parentheses usually means the counts and nesting must both be correct.

Example:
- `((()))` is balanced
- `(()` is not balanced
- `())(` is not balanced

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class BalancedParentheses {
    public static boolean isBalanced(String s) {
        Deque<Character> st = new ArrayDeque<>();

        for (char ch : s.toCharArray()) {
            if (ch == '(') {
                st.push(ch);
            } else if (ch == ')') {
                if (st.isEmpty() || st.peek() != '(') return false;
                st.pop();
            }
        }
        return st.isEmpty();
    }
}
```

### Template

```java
Deque<Character> st = new ArrayDeque<>();
for (char ch : s.toCharArray()) {
    if (ch == '(') st.push(ch);
    else {
        if (st.isEmpty()) return false;
        st.pop();
    }
}
return st.isEmpty();
```

### Complexity

- Time: O(n)
- Space: O(n)

### Edge Cases

- empty string
- only opening brackets
- only closing brackets
- very deep nesting

### Mistakes

- using count only for nested parentheses
- ignoring order

### Interview Questions

- is a string of parentheses balanced?
- check balanced brackets

### Company Questions

## Valid Parentheses

Valid parentheses usually includes all bracket types:
- `()`
- `[]`
- `{}`

The order must be correct and the types must match.

### Pattern Recognition

Use this when the string contains mixed bracket types and must be validated.

### Trigger Words

- `valid parentheses`
- `valid brackets`
- `expression validity`

### Observation

Closing bracket must match the most recent opening bracket of the same type.

### Brute Force

Try to pair brackets by repeatedly scanning and removing matching pairs.

### Optimal Solution

Use a stack of opening brackets.

### Visualization

```text
Input:  ()[]{}   -> valid
Input:  (]       -> invalid
Input:  ([)]     -> invalid
```

### Dry Run

String: `([{}])`

- `(` push
- `[` push
- `{` push
- `}` matches `{` pop
- `]` matches `[` pop
- `)` matches `(` pop
- stack empty -> valid

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class ValidParentheses {
    public static boolean isValid(String s) {
        Deque<Character> st = new ArrayDeque<>();

        for (char ch : s.toCharArray()) {
            if (ch == '(' || ch == '[' || ch == '{') {
                st.push(ch);
            } else {
                if (st.isEmpty()) return false;
                char top = st.peek();
                if ((ch == ')' && top != '(') ||
                    (ch == ']' && top != '[') ||
                    (ch == '}' && top != '{')) {
                    return false;
                }
                st.pop();
            }
        }
        return st.isEmpty();
    }
}
```

### Template

```java
Deque<Character> st = new ArrayDeque<>();
for (char ch : s.toCharArray()) {
    if (isOpen(ch)) {
        st.push(ch);
    } else {
        if (st.isEmpty() || !matches(st.peek(), ch)) return false;
        st.pop();
    }
}
return st.isEmpty();
```

### Complexity

- Time: O(n)
- Space: O(n)

### Edge Cases

- empty string should be valid
- starts with closing bracket
- odd length strings

### Mistakes

- forgetting to check stack empty before peek
- not validating bracket type
- treating other characters as brackets accidentally

### Interview Questions

- valid parentheses
- balanced brackets
- is expression valid?

### Company Questions

- parser-style bracket validation
- syntax checking problems

# Chapter 4: Expression Evaluation and Conversion
===============================================================================

## Introduction

Stacks are essential for expression handling because expressions have nesting,
precedence, and order constraints.

The three main notations are:
- infix
- prefix
- postfix

## Expression Forms

### Infix

Operator is between operands.

Example:

```text
A + B
2 * (3 + 4)
```

### Prefix

Operator comes before operands.

Example:

```text
+ A B
* 2 + 3 4
```

### Postfix

Operator comes after operands.

Example:

```text
A B +
2 3 4 + *
```

## Pattern Recognition

Use stack when the question mentions:
- expression
- prefix
- infix
- postfix
- evaluate
- convert
- precedence
- associativity

## Trigger Words

- `evaluate`
- `convert`
- `prefix`
- `infix`
- `postfix`
- `operator precedence`
- `parentheses`
- `expression`

## Observation

Operators need ordering rules.

Stacks help store operands or operators until the correct time to apply them.

## Brute Force

Try to manually calculate the expression from left to right without a stack.

That fails when precedence or nested parentheses appear.

## Optimal Solution

Use stack(s) to delay evaluation until:
- the operator order is valid
- the subexpression is complete

## Visualization

```text
Infix:   2 + 3 * 4
Postfix:  2 3 4 * +
Prefix:  + 2 * 3 4
```

## Dry Run

Expression: `2 + 3 * 4`

- `*` has higher precedence than `+`
- 3 and 4 combine first
- then add 2

## Precedence Table

```text
^  highest
* / %
+ -
```

`^` is usually right associative.

## 4.1 Postfix Evaluation

### Pattern Recognition

Use when expression is already in postfix and must be evaluated.

### Trigger Words

- `postfix evaluate`
- `reverse polish notation`
- `RPN`

### Observation

Postfix is easy to evaluate because every operator appears after its operands.

### Brute Force

Convert postfix to infix and then evaluate.

### Optimal Solution

Scan left to right:
- push operands
- when operator appears, pop two operands
- apply operator and push result

### Visualization

```text
Expression: 2 3 4 * +
Stack: [2]
       [2, 3]
       [2, 3, 4]
       operator * -> push 12
       operator + -> push 14
```

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class PostfixEvaluation {
    public static int evaluate(String[] tokens) {
        Deque<Integer> st = new ArrayDeque<>();

        for (String token : tokens) {
            if (isOperator(token)) {
                int b = st.pop();
                int a = st.pop();
                st.push(apply(a, b, token.charAt(0)));
            } else {
                st.push(Integer.parseInt(token));
            }
        }
        return st.pop();
    }

    private static boolean isOperator(String token) {
        return token.length() == 1 && "+-*/%^".indexOf(token.charAt(0)) != -1;
    }

    private static int apply(int a, int b, char op) {
        if (op == '+') return a + b;
        if (op == '-') return a - b;
        if (op == '*') return a * b;
        if (op == '/') return a / b;
        if (op == '%') return a % b;
        return (int) Math.pow(a, b);
    }
}
```

### Template

```java
for (token : postfix) {
    if (operand) push(token);
    else {
        b = pop();
        a = pop();
        push(apply(a, b, op));
    }
}
return top;
```

### Complexity

- Time: O(n)
- Space: O(n)

### Edge Cases

- division by zero
- malformed expression
- single operand only

### Mistakes

- popping operands in wrong order
- using one operand instead of two

### Interview Questions

- evaluate postfix expression
- evaluate RPN

### Company Questions

- calculator-style parsing
- expression engine

## 4.2 Prefix Evaluation

### Pattern Recognition

Use when expression is in prefix form and must be evaluated.

### Trigger Words

- `prefix evaluate`
- `polish notation`

### Observation

Prefix is evaluated from right to left.

### Brute Force

Convert prefix to infix and then compute.

### Optimal Solution

Scan right to left:
- push operands
- on operator, pop two operands
- apply operator and push result

### Visualization

```text
Expression: + 2 * 3 4
Scan from right
Stack eventually produces 14
```

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class PrefixEvaluation {
    public static int evaluate(String[] tokens) {
        Deque<Integer> st = new ArrayDeque<>();

        for (int i = tokens.length - 1; i >= 0; i--) {
            String token = tokens[i];
            if (isOperator(token)) {
                int a = st.pop();
                int b = st.pop();
                st.push(apply(a, b, token.charAt(0)));
            } else {
                st.push(Integer.parseInt(token));
            }
        }
        return st.pop();
    }

    private static boolean isOperator(String token) {
        return token.length() == 1 && "+-*/%^".indexOf(token.charAt(0)) != -1;
    }

    private static int apply(int a, int b, char op) {
        if (op == '+') return a + b;
        if (op == '-') return a - b;
        if (op == '*') return a * b;
        if (op == '/') return a / b;
        if (op == '%') return a % b;
        return (int) Math.pow(a, b);
    }
}
```

### Complexity

- Time: O(n)
- Space: O(n)

### Edge Cases

- one number
- malformed tokens

- scanning prefix from left to right

## 4.3 Infix Evaluation

### Pattern Recognition

Use this when the expression is written in standard form with parentheses and
operators.

### Trigger Words

- `infix`
- `calculate`
- `evaluate expression`
- `operator precedence`

### Observation

You need to delay operations until higher-precedence operators or parentheses are
resolved.

### Brute Force

Convert infix to postfix and evaluate postfix.

### Optimal Solution

Use two stacks:
- one for operands
- one for operators

### Visualization

```text
operands: [2, 3, 4]
operators: [+, *]
* evaluated before +
```

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class InfixEvaluation {
    public static int evaluate(String[] tokens) {
        Deque<Integer> values = new ArrayDeque<>();
        Deque<Character> ops = new ArrayDeque<>();

        for (String token : tokens) {
            if (token.equals("(")) {
                ops.push('(');
            } else if (token.equals(")")) {
                while (ops.peek() != '(') {
                    compute(values, ops.pop());
                }
                ops.pop();
            } else if (isOperator(token.charAt(0)) && token.length() == 1) {
                char op = token.charAt(0);
                while (!ops.isEmpty() && shouldPop(ops.peek(), op)) {
                    compute(values, ops.pop());
                }
                ops.push(op);
            } else {
                values.push(Integer.parseInt(token));
            }
        }

        while (!ops.isEmpty()) {
            compute(values, ops.pop());
        }
        return values.pop();
    }

    private static boolean isOperator(char ch) {
        return ch == '+' || ch == '-' || ch == '*' || ch == '/' || ch == '%' || ch == '^';
    }

    private static int precedence(char op) {
        if (op == '^') return 3;
        if (op == '*' || op == '/' || op == '%') return 2;
        if (op == '+' || op == '-') return 1;
        return 0;
    }

    private static boolean shouldPop(char top, char current) {
        if (top == '(') return false;
        int pTop = precedence(top);
        int pCur = precedence(current);
        if (pTop > pCur) return true;
        if (pTop < pCur) return false;
        return current != '^';
    }

    private static void compute(Deque<Integer> values, char op) {
        int b = values.pop();
        int a = values.pop();
        values.push(apply(a, b, op));
    }

    private static int apply(int a, int b, char op) {
        if (op == '+') return a + b;
        if (op == '-') return a - b;
        if (op == '*') return a * b;
        if (op == '/') return a / b;
        if (op == '%') return a % b;
        return (int) Math.pow(a, b);
    }
}
```

### Template

```java

    while (top operator has higher/equal precedence) apply it;
    push current operator;
}
apply remaining operators;
```

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class PrefixToInfix {
    public static String convert(String[] tokens) {
        Deque<String> st = new ArrayDeque<>();

        for (int i = tokens.length - 1; i >= 0; i--) {
            String token = tokens[i];
            if (isOperator(token)) {
                String a = st.pop();
                String b = st.pop();
                st.push("(" + a + token + b + ")");
            } else {
                st.push(token);
            }
        }
        return st.pop();
    }

    private static boolean isOperator(String token) {
        return token.length() == 1 && "+-*/%^".indexOf(token.charAt(0)) != -1;
    }
}
```

## 4.5 Infix to Postfix

### Pattern Recognition

Use this when standard infix must be transformed to postfix notation.

### Trigger Words

- `infix to postfix`
- `postfix conversion`
- `shunting`

### Observation

Operators are delayed on the stack until their precedence allows them to be
output.

### Brute Force

Build expression tree and do postorder traversal.

### Optimal Solution

Use an operator stack.

### Visualization

```text
Infix:  A + B * C
Postfix: A B C * +
```

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class InfixToPostfix {
    public static String convert(String[] tokens) {
        StringBuilder out = new StringBuilder();
        Deque<Character> ops = new ArrayDeque<>();

        for (String token : tokens) {
            char ch = token.charAt(0);

            if (token.length() > 1 || Character.isLetterOrDigit(ch)) {
                out.append(token).append(' ');
            } else if (ch == '(') {
                ops.push(ch);
            } else if (ch == ')') {
                while (!ops.isEmpty() && ops.peek() != '(') {
                    out.append(ops.pop()).append(' ');
                }
                ops.pop();
            } else {
                while (!ops.isEmpty() && shouldPop(ops.peek(), ch)) {
                    out.append(ops.pop()).append(' ');
                }
                ops.push(ch);
            }
        }

        while (!ops.isEmpty()) {
            out.append(ops.pop()).append(' ');
        }
        return out.toString().trim();
    }

    private static int precedence(char op) {
        if (op == '^') return 3;
        if (op == '*' || op == '/' || op == '%') return 2;
        if (op == '+' || op == '-') return 1;
        return 0;
    }

    private static boolean shouldPop(char top, char current) {
        if (top == '(') return false;
        int pTop = precedence(top);
        int pCur = precedence(current);
        if (pTop > pCur) return true;
        if (pTop < pCur) return false;
        return current != '^';
    }
}
```

### Template

```java
for each token in infix:
    if operand -> append to output
    else if '(' -> push
    else if ')' -> pop until '('
    else operator -> pop higher/equal precedence operators
```

- Time: O(n)
- Space: O(n)

- wrong precedence comparison
- forgetting to flush operators at end

# Chapter 5: Monotonic Stack Fundamentals
===============================================================================

## Introduction

A monotonic stack keeps elements in sorted-like order as you process the array.

There are two main forms:
- monotonic increasing stack
- monotonic decreasing stack

This is one of the most important stack interview patterns because it solves
next/previous greater or smaller problems in linear time.

## Pattern Recognition

Use monotonic stack when the question mentions:
- next greater
- previous greater
- next smaller
- previous smaller
- nearest larger
- nearest smaller
- span
- temperature
- histogram
- rectangle

## Trigger Words

- `next greater`
- `previous greater`
- `next smaller`
- `previous smaller`
- `nearest`
- `span`
- `distance`
- `temperature`
- `histogram`

## Observation

Each element is pushed and popped at most once.

That is why monotonic stack solutions are O(n).

## Brute Force

For every index, scan right or left until a valid greater/smaller element is
found.

That gives O(n^2).

## Optimal Solution

Maintain a stack that is always increasing or decreasing.

When the current element breaks the order:
- keep popping until the order is restored
- use the remaining top as the answer if needed
- push the current element

## Visualization

```text
Increasing stack example:
Bottom -> 1 -> 3 -> 6 -> Top

Decreasing stack example:
Bottom -> 9 -> 7 -> 4 -> Top
```

## Dry Run

Array: `3, 1, 2`

For increasing stack:
- push 3
- 1 breaks order -> pop 3, push 1
- 2 keeps increasing order -> push 2

## Generic Increasing Stack Template

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class IncreasingStackTemplate {
    public static void process(int[] arr) {
        Deque<Integer> st = new ArrayDeque<>();

        for (int x : arr) {
            while (!st.isEmpty() && st.peek() > x) {
                st.pop();
            }
            st.push(x);
        }
    }
}
```

## Generic Decreasing Stack Template

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class DecreasingStackTemplate {
    public static void process(int[] arr) {
        Deque<Integer> st = new ArrayDeque<>();

        for (int x : arr) {
            while (!st.isEmpty() && st.peek() < x) {
                st.pop();
            }
            st.push(x);
        }
    }
}
```

## Increasing vs Decreasing

Use increasing stack for:
- next smaller
- previous smaller
- histogram boundaries

Use decreasing stack for:
- next greater
- previous greater
- stock span
- daily temperatures

## Complexity

- Time: O(n)
- Space: O(n)

## Edge Cases

- empty array
- all increasing
- all decreasing
- duplicate values

## Mistakes

- using the wrong comparison direction
- storing values when indices are required
- forgetting to pop equal values when needed

- What is a monotonic stack?
- Why is it O(n)?
- When do you use increasing vs decreasing stack?

### Pattern Recognition

### Trigger Words

- `next greater`
- `nearest greater`
- `first bigger`
- `right side greater`

### Observation

For each element, we need the first bigger value that appears after it.

### Brute Force

### Visualization

- 2 -> next greater is 10
- 5 -> next greater is 10

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class NextGreaterElement {
    public static int[] nextGreater(int[] arr) {
        int n = arr.length;
        int[] ans = new int[n];
        Deque<Integer> st = new ArrayDeque<>();

        for (int i = n - 1; i >= 0; i--) {
            while (!st.isEmpty() && st.peek() <= arr[i]) {
                st.pop();
            }
            ans[i] = st.isEmpty() ? -1 : st.peek();
            st.push(arr[i]);
        }
        return ans;
    }
}
```

# Chapter 7: Histogram and Largest Rectangle
===============================================================================

## Introduction

Histogram problems are one of the clearest uses of monotonic increasing stack.

The classic question is to find the largest rectangle area under a histogram.

## Pattern Recognition

Use this when the problem mentions:
- histogram
- bars
- largest rectangle
- area
- width
- matrix rectangle

## Trigger Words

- `largest rectangle`
- `histogram`
- `area`
- `bars`
- `width`
- `previous smaller`
- `next smaller`

## Observation

For each bar, the maximal rectangle using that bar as the limiting height extends
until the first smaller bar on the left and right.

So the core idea is:
- find previous smaller
- find next smaller
- compute width

## Brute Force

For every bar, expand left and right until a smaller bar is found.

That is O(n^2).

## Optimal Solution

Use a monotonic increasing stack of indices.

When a smaller bar appears:
- pop taller bars
- compute area using the popped bar as height
- the current index becomes the right boundary

## Visualization

```text
heights: 2 1 5 6 2 3
max area = 10
```

## Dry Run

For `2, 1, 5, 6, 2, 3`:
- height 5 with width 2 gives area 10
- that is the maximum

## Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class LargestRectangleHistogram {
    public static int largestRectangleArea(int[] heights) {
        Deque<Integer> st = new ArrayDeque<>();
        int max = 0;
        int n = heights.length;

        for (int i = 0; i <= n; i++) {
            int h = (i == n) ? 0 : heights[i];

            while (!st.isEmpty() && h < heights[st.peek()]) {
                int height = heights[st.pop()];
                int right = i;
                int left = st.isEmpty() ? -1 : st.peek();
                int width = right - left - 1;
                max = Math.max(max, height * width);
            }
            st.push(i);
        }

        return max;
    }
}
```

## Template

```java

import java.util.ArrayDeque;
import java.util.Deque;

public class SimplifyPath {
    public static String simplify(String path) {
        Deque<String> st = new ArrayDeque<>();
        String[] parts = path.split("/");

        for (String part : parts) {
            if (part.isEmpty() || part.equals(".")) {
                continue;
            }
            if (part.equals("..")) {
                if (!st.isEmpty()) st.pop();
            } else {
                st.push(part);
            }
        }

        if (st.isEmpty()) return "/";

        StringBuilder sb = new StringBuilder();
        while (!st.isEmpty()) {
            sb.append("/").append(st.removeLast());
        }
        return sb.toString();
    }
}
```

```java
public class RemoveAdjacentDuplicates {
    public static String removeDuplicates(String s) {
        StringBuilder st = new StringBuilder();

        for (char ch : s.toCharArray()) {
            int n = st.length();
            if (n > 0 && st.charAt(n - 1) == ch) {
                st.deleteCharAt(n - 1);
            } else {
                st.append(ch);
```

# Chapter 9: Min Stack and Max Stack
===============================================================================

## Introduction

Min stack and max stack are special stacks that can return the minimum or
maximum element in O(1) time.

They are classic design questions because they combine a normal stack with extra
state.

## Pattern Recognition

Use this when the problem asks for:
- current minimum
- current maximum
- get min in O(1)
- get max in O(1)
- stack with extra query

## Trigger Words

- `minimum`
- `maximum`
- `min stack`
- `max stack`
- `O(1) query`
- `special stack`

## Observation

A plain stack does not know the minimum or maximum of everything below the top.

So we must track extra information.

## Brute Force

Scan the whole stack every time min or max is requested.

That is O(n) per query.

## Optimal Solution

Maintain an extra stack:
- min stack stores the minimum seen so far
- max stack stores the maximum seen so far

## Visualization

```text
values:  [5, 3, 7, 2]
minSt :  [5, 3, 3, 2]
maxSt :  [5, 5, 7, 7]
```

## Dry Run

- push 5 -> min = 5, max = 5
- push 3 -> min = 3, max = 5
- push 7 -> min = 3, max = 7
- push 2 -> min = 2, max = 7

## 9.1 Min Stack

### Java Code

```java
import java.util.ArrayDeque;
import java.util.Deque;

public class MinStack {
    private Deque<Integer> st = new ArrayDeque<>();
    private Deque<Integer> minSt = new ArrayDeque<>();

    public void push(int x) {
        st.push(x);
        if (minSt.isEmpty() || x <= minSt.peek()) {
            minSt.push(x);
        }
    }

    public int pop() {
        int x = st.pop();
        if (x == minSt.peek()) {
            minSt.pop();
        }
        return x;
    }

    public int top() {
        return st.peek();
    }

    public int getMin() {
        return minSt.peek();
    }

    public boolean isEmpty() {
        return st.isEmpty();
    }
}
```

### Template

```java
if (minSt.isEmpty() || x <= minSt.peek()) minSt.push(x);
if (popped == minSt.peek()) minSt.pop();
```

# Chapter 11: Revision Sheet and Cheat Sheet
===============================================================================

## Revision Sheet

- Stack follows LIFO
- push/pop/peek are O(1)
- array stack uses top index
- linked list stack uses head node
- Java `Stack` is legacy and synchronized
- `ArrayDeque` is the preferred modern stack
- use stack for nesting, matching, reverse order, and backtracking
- monotonic stack solves next/previous greater/smaller in O(n)
- histogram uses monotonic increasing stack
- min stack tracks extra minimum state

## Cheat Sheet

- brackets -> matching pair stack
- `()` / `[]` / `{}` -> validate with stack
- expression -> operand/operator stack
- prefix -> scan right to left
- postfix -> scan left to right
- infix -> use operator precedence
- next greater -> decreasing stack
- next smaller -> increasing stack
- previous greater -> decreasing stack
- previous smaller -> increasing stack
- histogram -> previous smaller + next smaller
- stock span -> previous greater index
- daily temperatures -> next greater index
- adjacent duplicates -> stack simulation
- minimum query -> min stack
- maximum query -> max stack

## Common Mistakes

- using the wrong monotonic direction
- storing values when indices are required
- forgetting to pop equal values when strict comparison is needed
- not handling empty stack in bracket problems
- wrong operand order in expression evaluation
- forgetting sentinel values in histogram
- returning from `pop()` on an empty stack without checking

## 12.1 Array Stack Template

```java
class ArrayStack {
    private int[] arr;
    private int top = -1;

    ArrayStack(int capacity) {
        arr = new int[capacity];
    }

    void push(int x) {
        arr[++top] = x;
    }

    int pop() {
        return arr[top--];
    }

    int peek() {
        return arr[top];
    }

    boolean isEmpty() {
        return top == -1;
    }
}
```

## 12.2 Linked List Stack Template

```java
class LinkedStack {
    static class Node {
        int data;
        Node next;
        Node(int data) { this.data = data; }
    }

    private Node head;

    void push(int x) {
        Node node = new Node(x);
        node.next = head;
        head = node;
    }

    int pop() {
        int val = head.data;
        head = head.next;
        return val;
    }

    int peek() {
        return head.data;
    }
}
```

## 12.7 Infix to Postfix Template

```java
Deque<Character> ops = new ArrayDeque<>();
StringBuilder out = new StringBuilder();
for (String token : tokens) {
    if (operand) out.append(token).append(' ');
    else if (token.equals("(")) ops.push('(');
    else if (token.equals(")")) {
        while (ops.peek() != '(') out.append(ops.pop()).append(' ');
        ops.pop();
    } else {
        while (!ops.isEmpty() && precedence(ops.peek()) >= precedence(token.charAt(0))) {
            if (ops.peek() == '(') break;
            out.append(ops.pop()).append(' ');
        }
        ops.push(token.charAt(0));
    }
}
while (!ops.isEmpty()) out.append(ops.pop()).append(' ');
```
