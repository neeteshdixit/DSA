# Chapter 1: Complete Introduction to Linked List
===============================================================================

## Introduction

A linked list is a linear data structure made of nodes, where each node stores
data and a reference to the next node. Unlike arrays, linked list nodes do not
need to live next to each other in memory.

Hinglish idea:
Linked list ko train samjho. Har coach apne next coach ka address rakhta hai.
Data order me hota hai, but memory me continuous hona zaroori nahi hai.

Linked lists are one of the most important interview topics because they test:
- pointer thinking
- memory awareness
- edge-case handling
- in-place manipulation

In this document, interview code mostly uses `ListNode` style examples because
that is the most common DSA and LeetCode notation. If your project uses the
repo's `Node` class with getters and setters, the same logic applies.

## Why Linked List Exists

Linked lists exist to solve problems where array weaknesses hurt performance.

Arrays are great for random access, but costly for insertions and deletions in
the middle because elements must be shifted.

Linked lists are useful when:
- size changes often
- insert/delete happens frequently
- random access is not required
- we want to build higher-level structures like stacks, queues, deques, and LRU
  caches

## Memory Representation

A linked list does not store elements in contiguous positions like an array.
Instead, each node is an object, and each node stores a reference to the next
node.

Visualization:

```text
head
 |
 v
[10 | next] -> [20 | next] -> [30 | next] -> null
```

The `head` variable points to the first node. From there, we can reach every
other node by following `next` links.

## Node

A node is the basic building block of a linked list.

For a singly linked list node:
- data field stores the value
- next field stores the reference to the next node

For a doubly linked list node:
- data
- prev
- next

Example interview-style node:

```java
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
        this.next = null;
    }
}
```

## Reference

In Java, linked list links are stored using references to objects.

Important idea:
- `node1.next = node2` means node1 stores the reference of node2
- the actual node object is created separately on the heap

This is not raw pointer arithmetic like C/C++, but the mental model is similar.

## Heap Memory

Node objects are allocated on the heap.

Heap memory is where dynamically created objects live. Since linked list nodes
are created with `new`, they are stored in heap memory.

Example:

```java
ListNode head = new ListNode(10);
head.next = new ListNode(20);
```

Here:
- `head` variable is a reference
- actual `ListNode` objects are on the heap

## Stack Memory

Local variables such as `head`, `curr`, `prev`, `slow`, and `fast` are stored in
stack frames as references.

Example:

```java
ListNode head = new ListNode(10);
ListNode curr = head;
```

`head` and `curr` are reference variables. They point to the same heap object
until one of them is reassigned.

## Internal Working

Internally, linked list operations are all about changing references.

Common actions:
- create a node
- read current node
- move to next node
- relink nodes
- break or reconnect links

Traversal starts from `head`, then follows `next` until `null` or until a
stopping condition appears.

Insert/delete operations usually do not move elements. They only redirect
references.

## Advantages

- dynamic size
- easy insertion and deletion once the node is known
- no shifting cost like arrays
- useful for implementing stacks, queues, deque, and adjacency-like structures
- good for frequent structural changes

## Disadvantages

- no direct random access
- extra memory for links
- poor cache locality
- traversal is slower than array indexing in practice
- searching is still O(n)

## Array vs Linked List

Array:
- contiguous memory
- O(1) random access
- costly middle insert/delete
- fixed size in basic form

Linked list:
- non-contiguous memory
- O(n) access to nth element
- cheap insert/delete after pointer is known
- dynamic size

Short rule:
- need direct indexing -> array
- need flexible insert/delete -> linked list

## Java LinkedList Class

Java's `java.util.LinkedList` is a doubly linked list implementation.

Important facts:
- it implements `List` and `Deque`
- it supports insertion/removal at both ends efficiently
- random access by index is O(n)
- it is not as cache-friendly as arrays

Common methods:
- `addFirst()`
- `addLast()`
- `removeFirst()`
- `removeLast()`
- `getFirst()`
- `getLast()`

## Brute Force

Brute force in linked list problems usually means:
- repeated traversal from the head
- converting to array first
- nested scans for node positions
- copying values into another structure

This often works, but it usually wastes the linked list structure.

## Optimal Approach

The optimal approach usually uses pointers directly on the list:
- one pass when possible
- dummy node to simplify edge cases
- fast and slow pointers for middle/cycle
- reversal by changing links in-place
- map only when extra memory is truly needed

## Observation

Most linked list problems are not about values first. They are about links and
node relationships.

## Core Intuition

Think of each node as a box with one or two arrows.
Your job is to carefully redirect arrows without losing the rest of the list.

## Visualization

```text
head -> [1] -> [2] -> [3] -> null
```

## ASCII Diagram

```text
Single node:
[10 | next=null]

Three nodes:
head -> [10 | *] -> [20 | *] -> [30 | null]
```

## Dry Run

If you insert 5 at the beginning of `10 -> 20 -> 30`:
- create node 5
- point 5.next to old head
- move head to 5

Result:

```text
5 -> 10 -> 20 -> 30
```

## Java Code

```java
class ListNode {
    int val;
    ListNode next;

    ListNode(int val) {
        this.val = val;
    }
}
```

## Template Code

```java
ListNode curr = head;
while (curr != null) {
    // process current node
    curr = curr.next;
}
```

## Line-by-Line Explanation

- `ListNode curr = head;` starts traversal from the first node
- `while (curr != null)` keeps moving until the list ends
- `// process current node` is where you read or update data
- `curr = curr.next;` advances to the next node

## Complexity

- traversal: O(n)
- access by index: O(n)
- insert/delete near known node: O(1)
- extra space for node links: O(n) overall for n nodes

## Edge Cases

- empty list
- one-node list
- two-node list
- head change during insert/delete
- tail change during insert/delete

## Common Mistakes

- losing the `next` reference before rewiring
- forgetting to update `head`
- not handling empty list
- not checking one-node and two-node edge cases
- using index thinking instead of pointer thinking

- Why are insertions easier than arrays?

# Chapter 2: Types of Linked Lists
===============================================================================

## Introduction

Linked lists come in different forms depending on how many pointers each node
stores and how the end of the structure is connected.

The four main types are:
- singly linked list
- doubly linked list
- circular linked list
- circular doubly linked list

## 2.1 Singly Linked List

### Pattern Recognition

Use singly linked list when each node only needs to know the next node.

### Trigger Words

- `next`
- `head`
- `traverse forward`
- `single direction`

### Brute Force

You can simulate with arrays or lists, but that misses the core pointer idea.

### Optimal Approach

Store only `next` references. This keeps memory usage lower than a doubly linked
list.

### Observation

Each node knows where to go next, but not where it came from.

### Intuition

This is the simplest linked list form and the base for most interview questions.

### Visualization

```text
head -> [10] -> [20] -> [30] -> null
```

### ASCII Diagram

```text
[10 | next] -> [20 | next] -> [30 | null]
```

### Java Code

```java
class SNode {
    int val;
    SNode next;

    SNode(int val) {
        this.val = val;
    }
}
```

### Template Code

```java
SNode curr = head;
while (curr != null) {
    System.out.print(curr.val + " ");
    curr = curr.next;
}
```

### Line-by-Line Explanation

- `curr` starts at `head`
- print current node value
- move to next node
- stop when next becomes null

### Complexity

- traversal: O(n)
- insert/delete after known node: O(1)
- search: O(n)

### Edge Cases

- empty list
- one node
- last node next must be null

### Common Mistakes

- forgetting to set last node's next to null
- losing the head reference

### Interview Questions

- implement singly linked list
- print all nodes
- insert at front/back

### Follow-up Questions

- Why is singly list simpler than doubly list?
- Why is backward traversal hard?

### Related Problems

- reverse list
- cycle detection
- merge two lists

## 2.2 Doubly Linked List

### Pattern Recognition

Use doubly linked list when traversal in both directions is required or when you
need easy deletion given a node reference.

### Trigger Words

- `prev`
- `next`
- `bidirectional`
- `backward`
- `deletion`

### Brute Force

A singly list can emulate backward movement by re-traversing from head, but that
is inefficient.

### Optimal Approach

Store both `prev` and `next` links.

### Observation

Each node knows both neighbors.

### Intuition

This helps when you need a deque-like structure or frequent deletions in the
middle.

### Visualization

```text
null <- [10] <-> [20] <-> [30] -> null
```

### ASCII Diagram

```text
[prev | 10 | next] <-> [prev | 20 | next] <-> [prev | 30 | next]
```

### Java Code

```java
class DNode {
    int val;
    DNode prev;
    DNode next;

    DNode(int val) {
        this.val = val;
    }
}
```

### Template Code

```java
DNode newNode = new DNode(5);
newNode.next = head;
if (head != null) {
    head.prev = newNode;
}
head = newNode;
```

### Line-by-Line Explanation

- create a new node
- point new node to old head
- update old head's prev link if it exists
- move head to new node

### Complexity

- insertion/deletion near node: O(1)
- traversal: O(n)
- extra memory: O(n) with extra prev links

### Edge Cases

- head insertion
- tail insertion
- removing the only node

### Common Mistakes

- forgetting to update both links
- breaking the chain by updating only one pointer

### Interview Questions

- why doubly linked list?
- how is deletion easier?
- how do you insert before a given node?

### Follow-up Questions

- compare singly and doubly linked list
- why is memory overhead larger?

### Related Problems

- LRU cache
- browser history
- deque implementation

## 2.3 Circular Linked List

### Pattern Recognition

Use circular linked list when the last node should connect back to the first.

### Trigger Words

- `circular`
- `round robin`
- `loop`
- `circle`
- `next of tail is head`

### Brute Force

You can store nodes in an array and rotate indices, but circular links give a
true cyclic structure.

### Optimal Approach

Set the tail's next pointer to head.

### Observation

There is no null at the end. You stop only when you reach the starting point
again.

### Intuition

Useful for round-robin scheduling and repeated cyclic traversal.

### Visualization

```text
head -> [10] -> [20] -> [30]
          ^                |
          |________________|
```

### ASCII Diagram

```text
[10] -> [20] -> [30]
 ^                 |
 |_________________|
```

### Java Code

```java
class CNode {
    int val;
    CNode next;

    CNode(int val) {
        this.val = val;
    }
}
```

### Template Code

```java
tail.next = head;
```

### Line-by-Line Explanation

- the tail no longer points to null
- it points back to the head
- traversal must stop using a visited check or a loop counter

### Complexity

- traversal: O(n)
- insert/delete depends on whether tail is tracked

### Edge Cases

- single-node circular list
- empty list
- infinite traversal risk

### Common Mistakes

- forgetting to stop traversal
- accidentally creating two cycles

### Interview Questions

- what is a circular linked list?
- how do you traverse it safely?

### Follow-up Questions

- how is it different from a regular linked list?
- where is it used?

### Related Problems

- Josephus-style elimination
- round robin simulation

## 2.4 Circular Doubly Linked List

### Pattern Recognition

Use this when you need both bidirectional movement and circularity.

### Trigger Words

- `circular doubly`
- `prev and next`
- `wrap around`
- `round robin in both directions`

### Brute Force

A regular doubly list can simulate circularity with special null handling, but
that adds extra checks.

### Optimal Approach

Connect tail.next to head and head.prev to tail.

### Observation

This structure has no null ends.

### Intuition

Very useful in deques and some cache or scheduling systems.

### Visualization

```text
     +-----------------------------+
     |                             |
head <-> [10] <-> [20] <-> [30] <-> tail
```

### ASCII Diagram

```text
[10] <-> [20] <-> [30]
 ^                   |
 |___________________|
```

### Java Code

```java
class CDNode {
    int val;
    CDNode prev;
    CDNode next;

    CDNode(int val) {
        this.val = val;
    }
}
```

### Template Code

```java
tail.next = head;
head.prev = tail;
```

### Line-by-Line Explanation

- tail.next creates the forward cycle
- head.prev creates the backward cycle
- the list can now be traversed endlessly in both directions

### Complexity

- traversal: O(n)
- insertion/deletion near known node: O(1)

### Edge Cases

- empty list
- one node circular doubly list

### Common Mistakes

- only linking one side of the cycle
- forgetting to maintain both directions on insert/delete

### Interview Questions

- define circular doubly linked list
- how do you insert at ends?

### Follow-up Questions

- how would you prevent infinite traversal?
- where would this be useful?

### Related Problems

- deque
- cyclic scheduler
- wrap-around navigation

# Chapter 3: Core Operations

## Introduction

Most linked list interview questions are just variations of a few core
operations:
- traversal
- length
- search
- insert
- delete

If these basics are solid, advanced questions become much easier.

## 3.1 Traversal

### Pattern Recognition

Use traversal when you need to visit every node once.

### Trigger Words

- `print all nodes`
- `visit each node`
- `traverse`
- `iterate through list`

### Brute Force

Convert the list into an array and then process it.

That works, but it misses the point of linked list pointer movement.

### Optimal Approach

Start from `head` and move through `next` links until the end.

### Observation

Traversal is the base operation for most other linked list tasks.

### Intuition

Every node can be reached by following the next reference exactly once.

### Visualization

```text
head -> 10 -> 20 -> 30 -> null
```

### ASCII Diagram

```text
[10] -> [20] -> [30] -> null
```

### Dry Run

- start at head
- process 10
- move to 20
- process 20
- move to 30
- process 30
- stop at null

### Java Code

```java
public static void traverse(ListNode head) {
    ListNode curr = head;
    while (curr != null) {
        System.out.print(curr.val + " ");
        curr = curr.next;
    }
}
```

### Template Code

```java
for (ListNode curr = head; curr != null; curr = curr.next) {
    // process curr
}
```

### Line-by-Line Explanation

- `curr` starts at the head
- `curr != null` keeps the loop alive while nodes remain
- print or process current node
- `curr = curr.next` moves forward

### Complexity

- Time: O(n)
- Space: O(1)

### Edge Cases

- empty list
- single node
- very long list

### Common Mistakes

- forgetting to move `curr`
- using `curr.next` before checking null

### Interview Questions

- print linked list
- traverse and count nodes

### Follow-up Questions

- how would you traverse backward in a doubly linked list?
- can traversal be done recursively?

### Related Problems

- display nodes in reverse
- print odd positions

## 3.2 Length

### Pattern Recognition

Use this when the question asks for size, count, or number of nodes.

### Trigger Words

- `length`
- `size`
- `count nodes`
- `number of elements`

### Brute Force

Store all nodes in another structure and use its size.

### Optimal Approach

Traverse once and increment a counter.

### Observation

Each visited node contributes exactly one to the count.

### Intuition

Length is just a traversal with counting.

### Visualization

```text
10 -> 20 -> 30 -> null
count = 3
```

### Java Code

```java
public static int length(ListNode head) {
    int count = 0;
    ListNode curr = head;
    while (curr != null) {
        count++;
        curr = curr.next;
    }
    return count;
}
```

### Template Code

```java
int count = 0;
for (ListNode curr = head; curr != null; curr = curr.next) {
    count++;
}
```

### Line-by-Line Explanation

- initialize count
- move through every node
- increase count once per node
- return total count

### Complexity

- Time: O(n)
- Space: O(1)

### Edge Cases

- empty list should return 0
- one node should return 1

### Common Mistakes

- returning number of links instead of number of nodes
- forgetting empty list

### Interview Questions

- find length of linked list
- count nodes

### Follow-up Questions

- can length be known without traversal?
- what if list is cyclic?

### Related Problems

- nth node from end
- middle node

## 3.3 Search

### Pattern Recognition

Use this when the question asks whether a value exists in the list.

### Trigger Words

- `search`
- `find`
- `contains`
- `exists`

### Brute Force

This is already a linear scan, because linked lists do not support random access.

### Optimal Approach

Traverse until you find the target or reach the end.

### Observation

In a linked list, searching is naturally O(n).

### Intuition

You can only know values by visiting nodes one by one.

### Visualization

```text
10 -> 20 -> 30 -> 40
search 30
```

### Java Code

```java
public static boolean search(ListNode head, int target) {
    ListNode curr = head;
    while (curr != null) {
        if (curr.val == target) return true;
        curr = curr.next;
    }
    return false;
}
```

### Template Code

```java
while (curr != null) {
    if (curr.val == target) return true;
    curr = curr.next;
}
return false;
```

### Line-by-Line Explanation

- move node by node
- compare current value with target
- return immediately when found
- return false if no match exists

### Complexity

- Time: O(n)
- Space: O(1)

### Edge Cases

- empty list
- target at head
- target at tail
- target missing

### Common Mistakes

- assuming binary search can be used
- forgetting the last node

### Interview Questions

- search an element in linked list
- find first occurrence

### Follow-up Questions

- how would you speed up repeated searches?
- why not use hashing instead?

### Related Problems

- contains duplicate detection
- membership checks

## 3.4 Insert Beginning

### Pattern Recognition

Use this when a new node should become the new head.

### Trigger Words

- `insert at beginning`
- `add first`
- `push front`
- `prepend`

### Brute Force

Shift all values to the right like an array.

### Optimal Approach

Create a new node and point it to the old head.

### Observation

Only two references change:
- new node.next
- head

### Intuition

The new node simply becomes the first box in the chain.

### Visualization

Before:

```text
head -> 10 -> 20 -> 30
```

After inserting 5:

```text
head -> 5 -> 10 -> 20 -> 30
```

### ASCII Diagram

```text
newNode -> oldHead
head = newNode
```

### Java Code

```java
public static ListNode insertBeginning(ListNode head, int val) {
    ListNode newNode = new ListNode(val);
    newNode.next = head;
    return newNode;
}
```

### Template Code

```java
ListNode node = new ListNode(val);
node.next = head;
head = node;
```

### Line-by-Line Explanation

- create new node
- make new node point to old head
- return new node as the new head

### Complexity

- Time: O(1)
- Space: O(1)

### Edge Cases

- empty list
- single node list

### Common Mistakes

- forgetting to return new head
- losing the old list by changing head too early

### Interview Questions

- insert at front
- push front in linked list

### Follow-up Questions

- how would this change in a doubly linked list?

### Related Problems

- delete beginning
- dummy node insertion

## 3.5 Insert End

### Pattern Recognition

Use this when a node must be appended to the tail.

### Trigger Words

- `insert at end`
- `append`
- `add last`
- `push back`

### Brute Force

Traverse to the end every time and then insert.

### Optimal Approach

If only head is given, traverse to the last node.
If tail is available, insert in O(1).

### Observation

Without a tail pointer, you must walk to the end first.

### Intuition

The final node's next should point to the new node.

### Visualization

Before:

```text
10 -> 20 -> 30 -> null
```

After inserting 40:

```text
10 -> 20 -> 30 -> 40 -> null
```

### Java Code

```java
public static ListNode insertEnd(ListNode head, int val) {
    ListNode newNode = new ListNode(val);
    if (head == null) return newNode;

    ListNode curr = head;
    while (curr.next != null) {
        curr = curr.next;
    }
    curr.next = newNode;
    return head;
}
```

### Template Code

```java
if (head == null) return newNode;
ListNode curr = head;
while (curr.next != null) curr = curr.next;
curr.next = newNode;
```

### Line-by-Line Explanation

- handle empty list first
- walk to last node
- connect last node to new node
- keep original head unchanged

### Complexity

- Time: O(n) without tail, O(1) with tail
- Space: O(1)

### Edge Cases

- empty list
- one node
- tail pointer available

### Common Mistakes

- forgetting the empty list case
- using `curr != null` instead of `curr.next != null`

### Interview Questions

- insert at end of linked list
- append node

### Follow-up Questions

- how do you keep tail pointer updated?

### Related Problems

- delete last node
- merge with tail pointer

## 3.6 Insert Position

### Pattern Recognition

Use this when a node must be inserted after traversing to a position or before a
given index.

### Trigger Words

- `insert at position`
- `insert after k nodes`
- `insert at index`

### Brute Force

Rebuild the list or shift values.

### Optimal Approach

Traverse to the node before the insertion point and relink pointers.

### Observation

You need the previous node and the current next node.

### Intuition

Insert in the middle by changing only two links.

### Visualization

Insert 25 after 20:

```text
10 -> 20 -> 30
10 -> 20 -> 25 -> 30
```

### Java Code

```java
public static ListNode insertAtPosition(ListNode head, int index, int val) {
    if (index == 0) return insertBeginning(head, val);

    ListNode curr = head;
    for (int i = 0; i < index - 1 && curr != null; i++) {
        curr = curr.next;
    }

    if (curr == null) return head;

    ListNode newNode = new ListNode(val);
    newNode.next = curr.next;
    curr.next = newNode;
    return head;
}
```

### Template Code

```java
ListNode prev = head;
for (int i = 0; i < index - 1; i++) {
    prev = prev.next;
}
ListNode node = new ListNode(val);
node.next = prev.next;
prev.next = node;
```

### Line-by-Line Explanation

- handle insertion at head separately
- move to node before target position
- create new node
- connect new node to rest of list
- connect previous node to new node

### Complexity

- Time: O(n)
- Space: O(1)

### Edge Cases

- insert at head
- index beyond list length
- empty list

### Common Mistakes

- moving one step too far
- forgetting to handle index 0
- breaking the rest of the chain

### Interview Questions

- insert node at position
- insert after kth node

### Follow-up Questions

- how would this change for doubly linked list?

### Related Problems

- partition list
- reorder based on position

## 3.7 Delete Beginning

### Pattern Recognition

Use this when the first node must be removed.

### Trigger Words

- `delete first`
- `remove head`
- `pop front`
- `erase beginning`

### Brute Force

Shift all remaining nodes left like an array.

### Optimal Approach

Move head to head.next and let the old head be garbage-collected.

### Observation

Deleting the first node only changes the head reference.

### Intuition

Skip the first node.

### Visualization

Before:

```text
head -> 10 -> 20 -> 30
```

After:

```text
head -> 20 -> 30
```

### Java Code

```java
public static ListNode deleteBeginning(ListNode head) {
    if (head == null) return null;
    return head.next;
}
```

### Template Code

```java
if (head == null) return null;
head = head.next;
```

### Line-by-Line Explanation

- check empty list

# Chapter 4: Fast Slow Pointer and Cycle Pattern

## Introduction

Fast slow pointer is one of the most important linked list patterns.

It uses two pointers moving at different speeds to solve:
- middle node
- cycle detection
- cycle start
- remove Nth node from end
- palindrome setup

## Pattern Recognition

Use fast slow pointer when the question mentions:
- middle
- cycle
- loop
- slow and fast
- nth from end
- meeting point

## Trigger Words

- `middle`
- `cycle`
- `loop`
- `fast`
- `slow`
- `nth from end`
- `meeting point`

## Brute Force

For middle:
- compute length first
- then walk to half

For cycle:
- store visited nodes in a set

For nth from end:
- compute length first
- then walk again

## Optimal Approach

Move one pointer slowly and the other quickly.

Why it works:
- for middle, the fast pointer reaches the end first
- for cycle, if a loop exists, fast eventually meets slow
- for nth from end, the fast pointer creates a gap

## Observation

Different speeds create useful distance information.

## Core Intuition

Fast pointer tells you where the end or loop is.
Slow pointer gives a midpoint or meeting point.

## Visualization

```text
fast moves 2 steps
```

- slow to 3, fast to 5

```java
public static ListNode middleNode(ListNode head) {

}
```

## 4.2 Detect Cycle

### Pattern Recognition

Use this when the list may loop back to a previous node.

### Trigger Words

- `cycle`
- `loop`
- `contains a loop`
- `circular`
- `Floyd`

### Brute Force

Keep a HashSet of visited nodes.

### Optimal Approach

Use slow and fast pointers.

If a cycle exists:
- fast eventually meets slow

If no cycle exists:
- fast reaches null

### Observation

In a cycle, the distance gap keeps shrinking until pointers meet.

### Core Intuition

The fast pointer moves around the loop faster than slow, so it must catch up.

### Visualization

```text
1 -> 2 -> 3 -> 4 -> 5
          ^         |
          |_________|
```

### Java Code

```java
public static boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) return true;
    }
    return false;
}
```

### Template Code

```java

}
return false;
```

### Line-by-Line Explanation

- move slow one step
- move fast two steps
- compare references, not values
- if equal, cycle exists
- if fast hits null, there is no cycle

## 4.3 Detect Cycle II

### Pattern Recognition

Use this when the interviewer asks for the starting node of the cycle.

### Trigger Words

- `cycle start`
- `starting node`
- `entry point`
- `loop start`

### Brute Force

Use a visited set and return the first repeated node.

### Optimal Approach

Use Floyd's meeting point property:
- find meeting point of slow and fast
- move one pointer from head
- move the other from meeting point
- they meet at cycle start

### Observation

Distance from head to cycle start equals distance from meeting point to cycle
start when both are moved one step at a time.

### Core Intuition

Meeting point is not the start, but it gives enough information to find it.

### Dry Run

For a cycle list:
- slow and fast meet inside the cycle
- reset one pointer to head
- move both one step
- meeting point becomes cycle start

### Java Code

```java
public static ListNode detectCycleStart(ListNode head) {
    ListNode slow = head, fast = head;

    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) break;
    }

    if (fast == null || fast.next == null) return null;

    slow = head;
    while (slow != fast) {
        slow = slow.next;
        fast = fast.next;
    }
    return slow;
}
```

### Template Code

```java

    fast = fast.next;
}
return slow;
```

### Line-by-Line Explanation

- first detect a meeting point
- if no meeting exists, return null
- reset slow to head
- move both pointers one step
- the meeting point is the cycle start

### Complexity

- Time: O(n)
- Space: O(1)

### Edge Cases

- no cycle
- cycle starts at head
- cycle of length 1

### Common Mistakes

- forgetting to check if cycle exists

### Observation

### Intuition

### Java Code

```java
public static ListNode nthFromEnd(ListNode head, int n) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;

    ListNode slow = dummy, fast = dummy;
    for (int i = 0; i <= n; i++) {
        fast = fast.next;
    }

    while (fast != null) {
        slow = slow.next;
        fast = fast.next;
    }

    return slow.next;
}
```

## 5.2 Merge Two Sorted Lists

### Pattern Recognition

Use this when two already sorted linked lists must be combined into one sorted
list.

### Trigger Words

- `merge`
- `sorted`
- `combine`
- `two lists`
- `stable order`

### Brute Force

Copy all nodes into an array, sort, and rebuild the list.

### Optimal Approach

Walk through both lists and attach the smaller current node to the result.

### Observation

Since both lists are already sorted, the smaller current head is always safe to
take next.

### Intuition

This is the linked list version of the merge step in merge sort.

### Visualization

```text
l1: 1 -> 3 -> 5
l2: 2 -> 4 -> 6
result: 1 -> 2 -> 3 -> 4 -> 5 -> 6
```

### ASCII Diagram

```text
dummy -> tail

```

### Java Code

```java
public static ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    ListNode dummy = new ListNode(0);
    ListNode tail = dummy;

    while (l1 != null && l2 != null) {
        if (l1.val <= l2.val) {
            tail.next = l1;
            l1 = l1.next;
        } else {
            tail.next = l2;
            l2 = l2.next;
        }
        tail = tail.next;
    }

    if (l1 != null) tail.next = l1;
    if (l2 != null) tail.next = l2;
    return dummy.next;
}
```

### Template Code

```java
ListNode dummy = new ListNode(0);

        tail.next = a;
        a = a.next;

        tail.next = b;
        b = b.next;
    }
    tail = tail.next;
}
tail.next = (a != null) ? a : b;
return dummy.next;
```

### Line-by-Line Explanation

- dummy provides a stable start
- tail tracks the last node in the merged list
- compare current heads of both lists
- attach the smaller node
- move the chosen list forward
- append remaining nodes at the end

- Time: O(n + m)

## 5.3 Merge K Lists

### Pattern Recognition

Use this when more than two sorted linked lists must be merged.

### Trigger Words

- `merge k`
- `multiple sorted lists`
- `priority`
- `heap`

### Brute Force

Merge lists one by one and repeatedly merge the result.

### Better Approach

Use a min heap to always choose the smallest current node among the k lists.

### Optimal Approach

Priority queue + merge pattern.

### Observation

The merge-two-lists logic extends naturally when the next smallest node is
selected from a heap.

### Intuition

Always take the smallest head among the active lists.

### Visualization

```text

List 2: 2 -> 5
List 3: 3 -> 6
heap picks 1, then 2, then 3, ...
```

### Java Code

```java
import java.util.PriorityQueue;

public static ListNode mergeKLists(ListNode[] lists) {
    PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);
    for (ListNode node : lists) {
        if (node != null) pq.offer(node);
    }

    ListNode dummy = new ListNode(0);
    ListNode tail = dummy;

    while (!pq.isEmpty()) {
        ListNode node = pq.poll();
        tail.next = node;
        tail = tail.next;
        if (node.next != null) pq.offer(node.next);
    }

    return dummy.next;
}
```

### Complexity

- Time: O(N log k)
- Space: O(k)

### Common Mistakes

- forgetting to push the next node of the extracted node
- comparing wrong values in priority queue

## 5.4 Two Pointer Pattern

### Pattern Recognition

Use two pointers when two list heads need to be aligned or compared.

### Trigger Words

- `intersection`
- `common node`
- `meet`
- `align`
- `two linked lists`

### Brute Force

For each node in one list, scan the other list for the same node.

### Optimal Approach

Move two pointers through both lists and switch heads when one reaches null.

### Observation

Switching heads makes both pointers travel the same total distance.

### Intuition

If an intersection exists, both pointers will arrive there at the same time.

### Visualization

```text
A: a1 -> a2 -> c1 -> c2
B: b1 -> b2 -> b3 -> c1 -> c2
```

### Java Code

```java
public static ListNode getIntersectionNode(ListNode headA, ListNode headB) {
    ListNode a = headA, b = headB;
    while (a != b) {
        a = (a == null) ? headB : a.next;
        b = (b == null) ? headA : b.next;
    }
    return a;
}
```

### Template Code

```java
ListNode a = headA, b = headB;
while (a != b) {
    a = (a == null) ? headB : a.next;
    b = (b == null) ? headA : b.next;
}
return a;
```

### Line-by-Line Explanation

- initialize both pointers at their respective heads
- if one pointer reaches null, send it to the other list's head
- keep moving until the pointers meet or both become null
- meeting node is the intersection, null means no intersection

### Complexity

- Time: O(n + m)
- Space: O(1)

### Edge Cases

- no intersection
- intersection at head

### Common Mistakes

- comparing values instead of node references
- not switching heads

## Optimal Approach

- prev
- curr

## Observation

## Core Intuition

Reverse by making each node point backward one step at a time.

## Visualization


## ASCII Diagram

## 6.1 Reverse Linked List Iteratively

### Dry Run

- prev = null, curr = 1
- save next = 2
- point 1.next to prev
- move prev to 1, curr to 2
- repeat until curr becomes null

### Java Code

```java
public static ListNode reverse(ListNode head) {
    ListNode prev = null;
    ListNode curr = head;

    while (curr != null) {
        ListNode next = curr.next;
        curr.next = prev;
        prev = curr;
        curr = next;
    }
    return prev;
}
```

### Template Code

```java
ListNode prev = null, curr = head;

    ListNode next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
}
return prev;
```

### Line-by-Line Explanation

- `prev` starts as null because new tail should point to null
- `curr` walks through the list
- `next` saves the remaining chain
- `curr.next = prev` reverses the pointer
- shift `prev` and `curr` forward
- return `prev` as the new head

### Complexity

- Time: O(n)
- Space: O(1)

### Edge Cases

- empty list
- one node
- two nodes

### Common Mistakes

- forgetting to save `next`
- losing the rest of the list

## 6.2 Reverse Recursively

### Pattern Recognition

Use recursion when the interviewer wants a recursive reverse or when recursion is
being explored as a thought exercise.

### Trigger Words

- `recursive reverse`
- `recursion`
- `reverse using recursion`

### Brute Force

Use an array or iterative reversal instead.

### Optimal Approach

Reverse the rest of the list first, then make the next node point back to the
current node.

### Observation

Recursive reverse is the same link reversal as iterative reverse, just expressed
with function calls.

### Intuition

The recursive call handles the smaller suffix, then the current node is attached
at the end.

### Dry Run

For `1 -> 2 -> 3`:
- recurse on `2 -> 3`
- recurse on `3`
- base case returns 3
- set 2.next.next = 2
- set 2.next = null

### Java Code

```java
public static ListNode reverseRecursive(ListNode head) {
    if (head == null || head.next == null) return head;

    ListNode newHead = reverseRecursive(head.next);
    head.next.next = head;
    head.next = null;
    return newHead;
}
```

### Template Code

```java
if (head == null || head.next == null) return head;
ListNode newHead = reverseRecursive(head.next);
head.next.next = head;
head.next = null;
return newHead;
```

### Line-by-Line Explanation

- base case handles empty or single-node list

## 6.3 Reverse Between

### Pattern Recognition

```java
public static ListNode reverseBetween(ListNode head, int left, int right) {
    if (head == null || left == right) return head;

    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode prev = dummy;

    for (int i = 1; i < left; i++) {
        prev = prev.next;

        ListNode move = curr.next;
        curr.next = move.next;
        move.next = prev.next;
        prev.next = move;
    }

    return dummy.next;
}
```

```java
public static ListNode reverseKGroup(ListNode head, int k) {
    if (k <= 1 || head == null) return head;

    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode groupPrev = dummy;

    while (true) {
        ListNode kth = groupPrev;
        for (int i = 0; i < k && kth != null; i++) {
            kth = kth.next;

            curr.next = prev;
            prev = curr;
            curr = next;

        groupPrev.next = kth;
        groupPrev = temp;
    }

    return dummy.next;
}
```

```java
public static boolean isPalindrome(ListNode head) {
    if (head == null || head.next == null) return true;

    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;

    ListNode second = reverse(slow);
    ListNode first = head;

    while (second != null) {

        first = first.next;
        second = second.next;
    }
    return true;
}
```

```java
public static ListNode rotateRight(ListNode head, int k) {
    if (head == null || head.next == null || k == 0) return head;

    int len = 1;
    ListNode tail = head;
    while (tail.next != null) {
        tail = tail.next;
        len++;
    }

    k %= len;
    if (k == 0) return head;

    tail.next = head;
    int stepsToNewTail = len - k - 1;
    ListNode newTail = head;
    for (int i = 0; i < stepsToNewTail; i++) {
        newTail = newTail.next;
    }

    ListNode newHead = newTail.next;
    newTail.next = null;
    return newHead;
}
```

```java
public static ListNode addTwoNumbers(ListNode l1, ListNode l2) {
```

## 8.1 Flatten List Concept

### Pattern Recognition

Use this when the list has a child/down pointer and all nodes must be turned into
a single linear list.

### Trigger Words

- `flatten`
- `child`
- `down`
- `multilevel`
- `nested list`

### Brute Force

Collect all values, sort or keep order as needed, and rebuild a new list.

### Optimal Approach

Use recursion or stack-based DFS to process child lists and stitch them into the
main list.

### Observation

The child chain should be inserted between the current node and the next node.

### Intuition

Flattening is like taking a tree-like list and making it linear again.

### Visualization

```text
1 -> 2 -> 3
     |
     7 -> 8
```

After flattening:

```text
1 -> 2 -> 7 -> 8 -> 3
```

### ASCII Diagram

```text
main: 1 -> 2 -> 3
              |
              7 -> 8
```

### Java Code

```java
class FlatNode {
    int val;
    FlatNode prev;
    FlatNode next;
    FlatNode child;
}

public static FlatNode flatten(FlatNode head) {
    if (head == null) return null;
    flattenDFS(head);
    return head;
}

private static FlatNode flattenDFS(FlatNode node) {
    FlatNode curr = node;
    FlatNode tail = node;

    while (curr != null) {
        FlatNode next = curr.next;
        if (curr.child != null) {
            FlatNode childHead = curr.child;
            FlatNode childTail = flattenDFS(childHead);

            curr.next = childHead;
            childHead.prev = curr;
            curr.child = null;

            if (next != null) {
                childTail.next = next;
                next.prev = childTail;
            }
            tail = childTail;
        } else {
            tail = curr;
        }
        curr = next;
    }
    return tail;
}
```

### Template Code

```java

// insert child list between current and next
// clear child pointer after connection
```

### Line-by-Line Explanation

- `flatten` starts the process
- helper walks the list and returns the tail
- if a child exists, flatten that child first
- connect current node to child head
- connect child tail to original next node
- clear child reference to avoid duplicate traversal

### Complexity

- Time: O(n)
- Space: O(depth) recursion or stack

### Edge Cases

- no child pointers
- child at head
- deeply nested child lists

### Common Mistakes

- forgetting to connect child tail to next
- not clearing child pointer
- losing the original next chain

### Interview Questions

- flatten list with child pointers

### Follow-up Questions

## 8.2 Clone Linked List With Random Pointer

### Pattern Recognition

Use this when each node has a random pointer in addition to next.

### Trigger Words

- `random pointer`
- `copy list`
- `clone linked list`
- `deep copy`

### Brute Force

Create nodes and use nested scans to find random pointer targets.

### Better Approach

Use a HashMap from original node to cloned node.

### Optimal Approach

For O(1) extra space, use the weaving method:
- insert clone node after each original node
- set random pointers using `original.random.next`
- detach clone list

### Observation

The challenge is not copying values, but copying pointer relationships.

### Intuition

Every original node should have a matching clone node.

### Visualization

```text
original: A -> B -> C
random:    A->C, B->A, C->B
clone: same structure but with new nodes
```

### Java Code

```java
import java.util.HashMap;
import java.util.Map;

class RandomNode {
    int val;
    RandomNode next;
    RandomNode random;

    RandomNode(int val) {
        this.val = val;
    }
}

public static RandomNode copyRandomList(RandomNode head) {
    if (head == null) return null;

    Map<RandomNode, RandomNode> map = new HashMap<>();
    RandomNode curr = head;

    while (curr != null) {
        map.put(curr, new RandomNode(curr.val));
        curr = curr.next;
    }

    curr = head;
    while (curr != null) {
        RandomNode clone = map.get(curr);
        clone.next = map.get(curr.next);
        clone.random = map.get(curr.random);
        curr = curr.next;
    }

    return map.get(head);
}
```

### Template Code

```java
Map<RandomNode, RandomNode> map = new HashMap<>();
// pass 1: create clones
// pass 2: connect next and random pointers
```

### Line-by-Line Explanation

- first pass creates clone nodes for every original node
- second pass wires next and random references
- map lookup ensures pointer targets are cloned nodes

### Complexity

- Time: O(n)
- Space: O(n)

### Edge Cases

- random pointer null
- list empty
- self-random node

### Common Mistakes

- shallow copy instead of deep copy
- forgetting random pointers
- not cloning nodes before wiring references

### Interview Questions

- clone linked list with random pointer
- copy list with random pointer

### Follow-up Questions

- can you do it in O(1) extra space?
- why is this called a deep copy?

### Related Problems

- graph clone
- tree clone with random links

# Chapter 10: Revision Sheet, Cheat Sheet, and Template Library

## Revision Sheet

## Core Facts

- linked list nodes are not stored contiguously
- head points to the first node
- tail node usually points to null in non-circular lists
- insert/delete after known node is O(1)
- access by index is O(n)
- searching is O(n)
- extra pointer memory is required

## When To Use Linked List

- frequent insert/delete
- dynamic size
- need for pointer-based manipulation
- deque-like behavior
- cycle, merge, reverse, and node-movement problems

## When Not To Use Linked List

- random access dominates
- cache locality matters a lot
- simple indexing is enough

## Time Complexity Quick View

- traversal: O(n)
- length: O(n)
- search: O(n)
- insert/delete at head: O(1)
- insert/delete at known node: O(1)
- insert/delete at end without tail: O(n)
- middle: O(n)
- cycle detection: O(n)
- merge two lists: O(n + m)
- reverse: O(n)
- reverse recursive: O(n) time, O(n) stack
- rotate: O(n)
- sort list: O(n log n)

## Space Complexity Quick View

- iterative basic operations: O(1)
- recursive reverse/sort: uses recursion stack
- random pointer clone with map: O(n)
- weaving clone method: O(1) extra space

## Cheat Sheet

- `head` may change -> use dummy node
- need midpoint -> fast slow pointer
- need cycle -> fast slow pointer
- need reverse -> prev curr next
- need sorted merge -> dummy + tail
- need intersection -> two pointers
- need palindrome -> middle + reverse
- need groups -> reverse in chunks
- need random pointer copy -> hashmap or weaving
- need flatten -> DFS/stack

```java
ListNode slow = head, fast = head;
```

### 10.12 Cycle Detection Template

```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;
}
return false;
```

### 10.13 Cycle Start Template

```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) break;
}
if (fast == null || fast.next == null) return null;
slow = head;
while (slow != fast) {
    slow = slow.next;
    fast = fast.next;
}
return slow;
```

### 10.14 Merge Two Lists Template

```java
ListNode dummy = new ListNode(0);
ListNode tail = dummy;
while (a != null && b != null) {
    if (a.val <= b.val) {
        tail.next = a;
        a = a.next;
    } else {
        tail.next = b;
        b = b.next;
    }
    tail = tail.next;
}
tail.next = (a != null) ? a : b;
return dummy.next;
```

### 10.15 Remove Nth From End Template

```java
ListNode dummy = new ListNode(0);
dummy.next = head;
ListNode slow = dummy, fast = dummy;
for (int i = 0; i <= n; i++) fast = fast.next;
while (fast != null) {
    slow = slow.next;
    fast = fast.next;
}
slow.next = slow.next.next;
return dummy.next;
```

### 10.16 Palindrome Template

```java
ListNode mid = middleNode(head);
ListNode second = reverse(mid);
ListNode first = head;
while (second != null) {
    if (first.val != second.val) return false;
    first = first.next;
    second = second.next;
}
return true;
```

### 10.17 Intersection Template

```java
ListNode a = headA, b = headB;
while (a != b) {
    a = (a == null) ? headB : a.next;
    b = (b == null) ? headA : b.next;
}
return a;
```

### 10.18 Reverse Between Template

```java
ListNode dummy = new ListNode(0);
dummy.next = head;
ListNode prev = dummy;
for (int i = 1; i < left; i++) prev = prev.next;
ListNode curr = prev.next;
for (int i = 0; i < right - left; i++) {
    ListNode move = curr.next;
    curr.next = move.next;
    move.next = prev.next;
    prev.next = move;
}
return dummy.next;
```

### 10.19 Reverse K Group Template

```java
ListNode dummy = new ListNode(0);
dummy.next = head;
ListNode groupPrev = dummy;
while (true) {
    ListNode kth = groupPrev;
    for (int i = 0; i < k && kth != null; i++) kth = kth.next;
    if (kth == null) break;
    ListNode groupNext = kth.next;
    ListNode prev = groupNext, curr = groupPrev.next;
    while (curr != groupNext) {
        ListNode next = curr.next;
        curr.next = prev;
        prev = curr;
        curr = next;
    }
    ListNode temp = groupPrev.next;
    groupPrev.next = kth;
    groupPrev = temp;
}
return dummy.next;
```

## Final Interview Cheat Sheet

- think in pointers, not indices
- save `next` before rewiring links
- use dummy node for head-changing operations
- use fast slow for middle and cycle
- use reverse for palindrome and reordering
- use two pointers for intersection
- use merge logic for sorted lists
- use DFS or stack for flattening
- use hashmap for random pointer cloning

## Final Note

If the problem looks like moving nodes, rearranging nodes, or remembering node
relationships, it is almost certainly a linked list pattern problem.
