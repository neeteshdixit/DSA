# Chapter 1: Introduction to Arrays
===============================================================================

## Introduction

An array is a collection of same-type elements stored in order. In interviews,
arrays matter because they are the base for traversal, searching, prefix sum,
sliding window, two pointers, binary search, and many more patterns.

Hinglish idea:
Array ko fixed line of boxes samjho. Har box ka index hota hai, aur us index
se element directly mil jata hai.

## Pattern Recognition

Use array thinking when the problem mentions:
- multiple values of same type
- index-based access
- max/min/sum/count
- sorted data
- subarray or continuous segment
- matrix or grid

## Trigger Words

- `index` -> position matters
- `sum` -> running total
- `count` -> frequency or tally
- `sorted` -> binary search may help
- `subarray` -> continuous segment
- `duplicate` -> repeated value handling

## Brute Force

For max element:

```java
int largest = arr[0];
for (int i = 0; i < arr.length; i++) {
    for (int j = 0; j < arr.length; j++) {
        if (arr[j] > arr[i]) {
            break;
        }
    }
}
```

Time: O(n^2), Space: O(1)

Why rejected:
It compares the same values repeatedly.

## Observation

Most basic array problems do not need nested loops. One scan is enough if you
keep a running answer.

## Core Intuition

Array = row of lockers. If you know the locker number, you can open it quickly.

## Visualization

```text
Index: 0  1  2  3  4
Value: 12 45  7 31 19
```

## Dry Run

Largest of [12, 45, 7, 31, 19]:
- start largest = 12
- compare 45 -> update
- compare 7 -> ignore
- compare 31 -> ignore
- compare 19 -> ignore

## Java Templates

```java
public class Main {
    public static void main(String[] args) {
        int[] arr = {12, 45, 7, 31, 19};
        int largest = arr[0];

        for (int i = 1; i < arr.length; i++) {
            if (arr[i] > largest) {
                largest = arr[i];
            }
        }

        System.out.println(largest);
    }
}
```

## Complexity Analysis

- Access by index: O(1)
- Traversal: O(n)
- Search in unsorted array: O(n)
- Space usually: O(1)

## Common Mistakes

- using `arr.length()`
- assuming max = 0 for negative arrays
- out-of-bounds at `arr[n]`
- thinking size can change

## Interview Follow-up Questions

- Difference between array and ArrayList?
- Why is access O(1)?
- Why is insertion in middle costly?

## Easy Problems

- print array
- find max/min
- sum of array
- search element

## Medium Problems

- move zeroes
- reverse array
- second largest
- duplicates

## Hard Problems

- trapping rain water
- first missing positive
- product except self

## Similar Questions

- traversal
- search
- count
- reverse

## Pattern Flowchart

```text
Array question -> need index access? -> array
```

## Memory Tricks

- `0 to n-1`
- fixed size
- same type

## One Page Revision Sheet

Array = ordered, same-type, fixed-size structure. Use it when direct access,
simple scanning, or index-based logic is needed.

mapping it to the right technique.

Hinglish:
Pehle problem ka shape pakdo, phir code likho.

Ask:
- sorted?
- contiguous?
- frequency?
- missing/duplicate?
- top K?
- intervals?

- `subarray` -> prefix sum/sliding window
- `pair` -> two pointers/hashmap
- `frequency` -> hashmap
- `missing` -> cyclic sort/xor
- `top K` -> heap

## Brute Force

Try every possible thing first. It is often correct but slow.

## Observation

Reduce repeated work. Use structure already present in the data.

## Core Intuition

Think like a doctor. Symptoms are keywords; pattern is the diagnosis.

## Visualization

```text
sorted -> binary search
contiguous -> sliding window
frequency -> hashmap
intervals -> merge interval
```

# Chapter 3: Basic Traversal Pattern
===============================================================================

## Introduction

Traversal means visiting each array element one by one. It is the base pattern
for scanning, counting, validating, and simple decision-making problems.

Hinglish:
Ek-ek element ko dekhna hi traversal hai.

## Pattern Recognition

Use traversal when the problem asks:
- print all elements
- sum
- max/min
- count
- search in unsorted array
- validate condition across full array

## Trigger Words

- `print`
- `sum`
- `count`
- `maximum`
- `minimum`
- `search`
- `check`

## Brute Force

Checking every element against every other element is unnecessary for many
basic questions.

## Observation

Keep a running answer while moving once through the array.

## Core Intuition

Like attendance in class: check one student, update record, move on.

## Visualization

```text
[12] [45] [ 7] [31] [19]
  ^
```

## Dry Run

Largest in [4, 2, 9, 1, 7]:
- start 4
- 2 ignored
- 9 update
- 1 ignored
- 7 ignored

## Java Templates

```java
public class Traversal {
    public static int max(int[] arr) {
        int best = arr[0];
        for (int i = 1; i < arr.length; i++) {
            if (arr[i] > best) best = arr[i];
        }
        return best;
    }
}
```

## Complexity Analysis

- Time: O(n)
- Space: O(1)

## Common Mistakes

- wrong neutral initialization
- forgetting empty-array handling

## Interview Follow-up Questions

## Easy Problems

## Hard Problems

## Similar Questions

# Chapter 4: Prefix Sum Pattern
===============================================================================

## Introduction

Prefix Sum stores cumulative totals so that range sum queries can be answered
quickly. It is a classic time-for-space tradeoff.

Hinglish:
Ab tak ka total yaad rakho, phir range ka sum jaldi nikal jayega.

## Pattern Recognition

Use prefix sum when the problem asks:
- sum from l to r
- subarray sum
- cumulative total
- many repeated range queries

## Trigger Words

- `range`
- `query`
- `subarray`
- `cumulative`
- `running sum`
- `prefix`

## Brute Force

Recompute the range sum every time by scanning the whole segment.

```java
public class RangeSumBrute {
    public static int rangeSum(int[] arr, int l, int r) {
        int sum = 0;
        for (int i = l; i <= r; i++) sum += arr[i];
        return sum;
    }
}
```

Time per query: O(n) worst case.

## Observation

Build a prefix array once, then answer any range sum with subtraction.

## Core Intuition

Like bank balance history: total till now minus total before left boundary.

## Visualization

```text
arr    : [2, 1, 3, 4, 5]
prefix : [0, 2, 3, 6, 10, 15]
```

## Dry Run

Range sum 1..3:
- answer = prefix[4] - prefix[1] = 10 - 2 = 8

## Java Templates

```java
public class PrefixSum {
    public static long[] build(int[] arr) {
        long[] prefix = new long[arr.length + 1];
        for (int i = 0; i < arr.length; i++) {
            prefix[i + 1] = prefix[i] + arr[i];
        }
        return prefix;
    }

    public static long rangeSum(long[] prefix, int l, int r) {
        return prefix[r + 1] - prefix[l];
    }
}
```

## Complexity Analysis

- Build: O(n)
- Query: O(1)
- Space: O(n)

## Common Mistakes

- off-by-one errors
- using int for large sums
- confusing 0-based and 1-based prefix logic

## Interview Follow-up Questions

- Why prefix sum?
- Why not sliding window?
- What if the array changes later?

## Easy Problems

- running sum
- range sum query
- first k elements sum

## Medium Problems

- pivot index
- equilibrium index
- subarray sum equals K

## Hard Problems

- count zero-sum subarrays
- subarray sum divisible by K

## Similar Questions

- range sum
- cumulative sum
- subarray sum

## Pattern Flowchart

```text
Need repeated range sum? -> prefix sum
```

## Memory Tricks

- total till r minus total before l

## One Page Revision Sheet

Prefix Sum = preprocess cumulative totals once, answer range sums fast.

# Chapter 5: Sliding Window Pattern
===============================================================================

## Introduction

Sliding Window is used when the answer depends on a continuous segment of the
array. Instead of recomputing every range, keep a moving window and update it.

Hinglish:
Window ko move karo, poori array ko repeat mat karo.

## Pattern Recognition

Use it for:
- longest or shortest subarray
- fixed window size
- at most K
- exactly K
- contiguous segment optimization

## Trigger Words

- `longest`
- `shortest`
- `subarray`
- `contiguous`
- `window`
- `at most`
- `exactly`

## Brute Force

Check every subarray and compute the answer from scratch.

```java
public class WindowBrute {
    public static int maxSumSizeK(int[] arr, int k) {
        int best = Integer.MIN_VALUE;
        for (int i = 0; i + k <= arr.length; i++) {
            int sum = 0;
            for (int j = i; j < i + k; j++) sum += arr[j];
            best = Math.max(best, sum);
        }
        return best;
    }
}
```

## Observation

When a window moves one step:
- one element enters
- one element leaves

So update instead of recompute.

## Core Intuition

Sliding Window is like a camera frame moving on a road.

## Visualization

```text
[1 2 3 4 5]
 [1 2 3]
   [2 3 4]
     [3 4 5]
```

## Dry Run

Fixed window size 3:
- sum(1,2,3) = 6
- move: remove 1, add 4 -> 9
- move: remove 2, add 5 -> 12

## Java Templates

```java
public class SlidingWindow {
    public static int maxSumSizeK(int[] arr, int k) {
        int sum = 0;
        for (int i = 0; i < k; i++) sum += arr[i];
        int best = sum;

        for (int i = k; i < arr.length; i++) {
            sum += arr[i];
            sum -= arr[i - k];
            best = Math.max(best, sum);
        }
        return best;
    }
}
```

## Complexity Analysis

- Time: O(n)
- Space: O(1)

## Common Mistakes

- recomputing the whole window
- mixing fixed and variable window rules
- forgetting shrink condition

## Interview Follow-up Questions

- Why sliding window?
- Why not prefix sum?
- What if negatives exist?

## Easy Problems

- max sum of size K
- first negative in every window

## Medium Problems

- longest substring without repeat
- minimum size subarray sum
- at most K distinct

## Hard Problems

- exactly K distinct
- window with multiple constraints

## Similar Questions

- fixed window
- variable window
- at most K
- exactly K

## Pattern Flowchart

```text
Continuous segment? -> sliding window
```

## Memory Tricks

- expand, shrink, update
- one enters, one leaves

## One Page Revision Sheet

Sliding Window = maintain a moving contiguous segment and update in O(1).

# Chapter 6: Two Pointer Pattern
===============================================================================

## Introduction

Two Pointer is used when two positions can solve the problem faster than brute
force. It is especially powerful on sorted arrays.

Hinglish:
Do pointers ka matlab do ends ya do positions ka smart use.

## Pattern Recognition

Use it for:
- pair sum
- reverse array
- remove duplicates
- palindrome style checks

## Trigger Words

- `pair`
- `sorted`
- `reverse`
- `duplicate`
- `left and right`

## Brute Force

Try every pair.

```java
public class TwoPointerBrute {
    public static boolean hasPair(int[] arr, int target) {
        for (int i = 0; i < arr.length; i++) {
            for (int j = i + 1; j < arr.length; j++) {
                if (arr[i] + arr[j] == target) return true;
            }
        }
        return false;
    }
}
```

## Observation

In sorted arrays, move left or right based on whether the sum is too small or
too large.

## Core Intuition

Two people walking from both ends of a bridge toward each other.

## Visualization

```text
[1 2 3 4 5 6]
 L         R
```

## Dry Run

Target 7:
- 1 + 6 = 7 -> found

## Java Templates

```java
public class TwoPointer {
    public static boolean pairSumSorted(int[] arr, int target) {
        int l = 0, r = arr.length - 1;
        while (l < r) {
            int sum = arr[l] + arr[r];
            if (sum == target) return true;
            if (sum < target) l++;
            else r--;
        }
        return false;
    }
}
```

## Complexity Analysis

- Time: O(n)
- Space: O(1)

## Common Mistakes

- using it on unsorted arrays without logic
- moving pointers randomly
- forgetting `l < r`

## Interview Follow-up Questions

- Why two pointers?
- Why not hash map?
- Why sorted data helps?

## Easy Problems

- reverse array
- pair sum in sorted array
- remove duplicates

## Medium Problems

- 3Sum style
- squares of sorted array
- container style questions

## Hard Problems

- trapping rain water
- advanced in-place rearrangements

## Similar Questions

- pair
- reverse
- palindrome
- sorted comparisons

## Pattern Flowchart

```text
Sorted + pair/ends -> two pointers
```

## Memory Tricks

- left rises, right falls
- adjust based on sum

## One Page Revision Sheet

Two Pointer = use two indices to reduce search space, especially in sorted data.

# Chapter 7: Kadane Algorithm
===============================================================================

## Introduction

Kadane solves maximum subarray sum in one pass. The key idea is to drop a bad
running sum and start fresh when needed.

Hinglish:
Negative baggage ko carry mat karo.

## Pattern Recognition

Use Kadane for:
- maximum subarray
- best contiguous sum
- largest segment gain

## Trigger Words

- `maximum`
- `subarray`
- `contiguous`
- `sum`

## Brute Force

Check every subarray sum.

## Observation

At every index choose:
- extend current subarray
- start new from current element

## Core Intuition

Like carrying luggage. If luggage becomes harmful, drop it.

## Visualization

```text
arr:  [2, -3, 4, -1, 2, 1, -5, 4]
best:   2   2  4   4  5  6   6  6
```

## Dry Run

- current = 2
- -3 makes it worse
- restart at 4
- best grows to 6

## Java Templates

```java
public class Kadane {
    public static int maxSubarray(int[] arr) {
        int current = arr[0];
        int best = arr[0];

        for (int i = 1; i < arr.length; i++) {
            current = Math.max(arr[i], current + arr[i]);
            best = Math.max(best, current);
        }
        return best;
    }
}
```

## Complexity Analysis

- Time: O(n)
- Space: O(1)

## Common Mistakes

- initializing answer to 0 for all-negative arrays
- confusing current and best

## Interview Follow-up Questions

- What if all numbers are negative?
- Can you return indices?
- Can this become circular?

## Easy Problems

- maximum subarray sum
- largest contiguous gain

## Medium Problems

- circular subarray sum
- minimum subarray sum

## Hard Problems

- 2D Kadane
- constrained segment problems

## Similar Questions

- best segment
- throw away negative baggage

## Pattern Flowchart

```text
Contiguous + maximum sum -> Kadane
```

## Memory Tricks

- keep or drop
- extend or restart

## One Page Revision Sheet

Kadane = one pass, reset when current sum becomes harmful.

# Chapter 10: Binary Search
===============================================================================

## Introduction

Binary Search works on sorted arrays. It discards half of the search space on
every step, making search much faster than linear scan.

Hinglish:
Sorted ho to aadhi array ko ek saath ignore kar sakte ho.

## Pattern Recognition

Use it for:
- search in sorted array
- first/last occurrence
- insertion position
- floor/ceil style questions

## Trigger Words

- `sorted`
- `search`
- `position`
- `first`
- `last`
- `insert`

## Brute Force

Linear scan through the array.

## Observation

Middle element tells us which half to keep.

## Core Intuition

Dictionary searching: never read page by page if you can jump to the middle.

## Visualization

```text
[1 3 5 7 9 11 13]
      mid
```

## Dry Run

Search 7:
- middle = 7 -> found

## Java Templates

```java
public class BinarySearch {
    public static int search(int[] arr, int target) {
        int l = 0, r = arr.length - 1;
        while (l <= r) {
            int mid = l + (r - l) / 2;
            if (arr[mid] == target) return mid;
            if (arr[mid] < target) l = mid + 1;
            else r = mid - 1;
        }
        return -1;
    }
}
```

## Complexity Analysis

- Time: O(log n)
- Space: O(1)

## Common Mistakes

- using it on unsorted data
- wrong mid update
- infinite loop due to bad boundaries

## Interview Follow-up Questions

- Why binary search?
- Why sorted data?
- Can you handle duplicates?

## Easy Problems

- search element
- insert position
- first occurrence

## Medium Problems

- last occurrence
- floor and ceil
- search in rotated array

## Hard Problems

- binary search on answer
- rotated array with duplicates

## Similar Questions

- search
- position
- occurrence

## Pattern Flowchart

```text
Sorted? -> binary search
```

## Memory Tricks

- halve the space
- sorted means search smart

## One Page Revision Sheet

Binary Search = halve the problem each time on sorted data.

# Chapter 11: Binary Search on Answer
===============================================================================

## Introduction

Sometimes the answer itself is not directly visible. In that case, you guess a
candidate answer and check if it is feasible. If yes, move toward a better one.

Hinglish:
Pehle answer guess karo, phir feasibility check karo.

## Pattern Recognition

Use it for:
- minimum possible answer
- maximum possible answer
- capacity or allocation problems
- can we do it?

## Trigger Words

- `minimum possible`
- `maximum possible`
- `feasible`
- `capacity`
- `can we`

## Brute Force

Try every possible answer one by one.

## Observation

If a candidate works, then answers on one side may also work. That monotonic
property is what makes binary search possible.

## Core Intuition

Guess and verify, like choosing the smallest truck that can carry all boxes.

## Visualization

```text
answer space: 1 2 3 4 5 6 7 8 9
               ^
```

## Dry Run

If mid is feasible:
- try smaller answer

If not feasible:
- try larger answer

## Java Templates

```java
public class BinarySearchAnswer {
    public static int solve(int[] arr) {
        int l = 0, r = 100; // example bounds
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (canDo(arr, mid)) r = mid;
            else l = mid + 1;
        }
        return l;
    }

    private static boolean canDo(int[] arr, int mid) {
        return true;
    }
}
```

## Complexity Analysis

- Time: O(n log answer)
- Space: O(1)

## Common Mistakes

- wrong bounds
- no monotonic condition
- confusing direct search with answer search

## Interview Follow-up Questions

- Why binary search works here?
- What is the feasibility function?

## Easy Problems

- smallest divisor
- minimum capacity

## Medium Problems

- Koko eating bananas
- book allocation

## Hard Problems

- split array largest sum
- complex partition problems

## Similar Questions

- feasible
- minimum possible
- maximum possible

## Pattern Flowchart

```text
Need answer, not element? -> binary search on answer
```

## Memory Tricks

- guess, test, narrow
- feasibility must be monotonic

## One Page Revision Sheet

Binary Search on Answer = search over answer space using feasibility checks.

# Chapter 12: Merge Interval Pattern
===============================================================================

## Introduction

Merge Interval handles overlap between ranges. Sort intervals first, then merge
if they touch or overlap.

Hinglish:
Time blocks overlap ho to ek block bana do.

## Pattern Recognition

Use it when you see:
- intervals
- overlap
- meeting
- schedule
- start and end

## Trigger Words

- `interval`
- `overlap`
- `merge`
- `meeting`
- `schedule`

## Brute Force

Compare every interval with every other interval.

## Observation

Sorting by start time makes merging easy.

## Core Intuition

Railway platform analogy: overlapping train times need shared platform logic.

## Visualization

```text
|----|
   |------|
```

## Dry Run

After sorting:
- if current starts after last merged ends, add new interval
- else extend last merged end

## Java Templates

```java
import java.util.*;

public class MergeInterval {
    public static int[][] merge(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);
        List<int[]> res = new ArrayList<>();

        for (int[] cur : intervals) {
            if (res.isEmpty() || res.get(res.size() - 1)[1] < cur[0]) {

                    Math.max(res.get(res.size() - 1)[1], cur[1]);
            }
        }

        return res.toArray(new int[0][]);
    }
}
```

```java
public class CyclicSort {
    public static void sort(int[] arr) {
        int i = 0;
        while (i < arr.length) {

            }
```

## Visualization

```text
[4 5 6 7 0 1 2]
```

## Java Templates

```java
public class RotatedSearch {
    public static int search(int[] arr, int target) {
        int l = 0, r = arr.length - 1;
        while (l <= r) {
            int mid = l + (r - l) / 2;
            if (arr[mid] == target) return mid;
            if (arr[l] <= arr[mid]) {
                if (arr[l] <= target && target < arr[mid]) r = mid - 1;
                else l = mid + 1;
            } else {
                if (arr[mid] < target && target <= arr[r]) l = mid + 1;
                else r = mid - 1;
            }
        }
        return -1;
    }
}
```

## Java Templates

```java
import java.util.Stack;

public class MonotonicStack {
    public static int[] nextGreater(int[] arr) {
        int[] ans = new int[arr.length];
        Stack<Integer> st = new Stack<>();
        for (int i = arr.length - 1; i >= 0; i--) {
            while (!st.isEmpty() && st.peek() <= arr[i]) st.pop();
```
